# V2-SC-004 — Implement Versioned Protocol Configuration Registry

## Overview

Implement a configuration registry that validates parameter bounds, versions parameter sets, and lets claims reference immutable snapshots.

## Problem Context

Claims must freeze the economic and timing rules under which they were created. Reading mutable global values during later settlement would allow governance changes to alter active claims retroactively.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Represent supported assets, bounty/stake bounds, weight cap, durations, participation thresholds, confidence, challenge bond, appeal multiplier, allocation basis points, reputation bounds, and pause cooldowns.
- Validate nonzero durations, safe numeric ranges, supported assets, and allocation totals of exactly 10,000 basis points.
- Create immutable parameter-set IDs and getters optimized for module reads.
- Restrict new versions to timelocked governance hooks while preserving all prior versions.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- Reject fee-on-transfer or unsupported assets unless an approved adapter exists.
- Prevent retroactive mutation or deletion of a referenced parameter set.
- Use overflow-safe types and deterministic rounding policy identifiers.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Unit tests for every bound and invalid combination.
- Fuzz tests for basis-point sums and numeric extremes.
- Regression test proving an active claim retains its original parameter version.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.
