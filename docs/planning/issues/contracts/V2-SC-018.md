# V2-SC-018 — Implement Appeal Aggregation and Final Dispute Resolution

## Overview

Aggregate the closed appeal round, finalize the claim, and record deterministic challenger-bond treatment instructions.

## Problem Context

V2 allows one appeal and prohibits governance from deciding individual claims. The final result must be derived from frozen appeal inputs and become immutable.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Require Disputed state and a closed appeal round.
- Apply canonical aggregation and appeal thresholds.
- Make the appeal result the final claim outcome and prohibit recursive appeals.
- Determine whether the challenge succeeded by comparing provisional and final outcomes according to the specification.
- Emit AppealFinalized and ClaimFinalized with all result and bond-disposition fields.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- Caller cannot choose the final outcome or bond disposition.
- Finalization must be idempotent and irreversible.
- Do not distribute funds directly; produce typed accounting instructions.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Changed outcome, unchanged outcome, and inconclusive appeal tests.
- Early, repeated, paused, and wrong-state tests.
- Property test that finalized claims cannot transition again.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.
