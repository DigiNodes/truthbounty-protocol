# V2-SC-017 — Implement Appeal Verification Round

## Overview

Create and operate the single appeal round using the canonical verification and stake primitives.

## Problem Context

A dispute requires a second deterministic verification round with frozen higher participation requirements. Reusing mutable first-round state would make appeal behavior ambiguous.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Open one appeal round from the dispute record with frozen duration, minimum stake, participation multiplier, and weight cap.
- Permit stake-backed True or False submissions under the same one-address-one-position rule.
- Keep first-round and appeal records isolated while preserving claim association.
- Close the appeal permissionlessly after its deadline and emit canonical round events.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- Prevent multiple appeal rounds or recursive appeal creation.
- Do not let first-round storage mutate when appeal votes arrive.
- Apply the same custody and duplicate protections as V2-SC-010.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests
