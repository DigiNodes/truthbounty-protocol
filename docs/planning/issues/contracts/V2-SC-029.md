# V2-SC-029 — Implement Transparent Proxy and Upgrade Administration

## Overview

Implement the transparent ERC-1967 proxy pattern, timelock-owned ProxyAdmin, initializer protection, and upgrade validation hooks.

## Problem Context

Upgradeable modules need one controlled pattern. Mixed proxy styles, initialized implementations, or deployer-owned ProxyAdmin would create upgrade and storage risks.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Define which modules are proxied and document immutable exceptions.
- Deploy implementations with initializers disabled and proxies initialized once.
- Transfer ProxyAdmin ownership to TimelockController.
- Require the 7-day upgrade delay and emit module/version updates.
- Integrate storage-layout and interface compatibility prechecks.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- No deployer or guardian upgrade authority.
- Reject zero, EOA, incompatible, and already-used implementations.
- Prevent initializer replay and selector-clash hazards.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Initialization, ownership transfer, authorized upgrade, early upgrade, unauthorized upgrade, and replay tests.
- Storage-preservation test across a sample upgrade.
- ProxyAdmin and manifest reconciliation test.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.

## Acceptance Criteria

- [ ] All upgradeable modules follow one documented pattern.
