# V2-SC-013 — Implement Deterministic Aggregation Engine

## Overview

Implement integer-only aggregation over frozen verification records and return True, False, or Inconclusive.

## Problem Context

Outcome calculation must be reproducible by every node and independent of submission order. Floating point, mutable weights, sorting side effects, or caller-selected inputs would create consensus risk.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Sum frozen True and False effective weights using checked integer arithmetic.
- Return Inconclusive for zero participation, exact ties, or threshold failure signals supplied by the threshold module.
- Prevent caller-provided weight substitution and preserve round identity.
- Store or return a canonical aggregation record with weights, counts, outcome, and parameter version.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- Aggregation must be order-independent and deterministic.
- Prevent arithmetic overflow and denial of service from unbounded participant counts.
- A caller may trigger aggregation but cannot choose the result.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Unanimous, mixed, weighted-majority, tie, and zero-participation tests.
- Permutation property test proving order independence.
- Fuzz tests for stake distributions and numeric bounds.
- Repeat-aggregation consistency test.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.
