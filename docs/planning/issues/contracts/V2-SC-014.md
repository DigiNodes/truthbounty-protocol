# V2-SC-014 — Implement Participation Threshold and Confidence Rules

## Overview

Implement minimum verifier count, total effective weight, confidence basis points, and appeal multiplier evaluation.

## Problem Context

A weight majority alone is insufficient when participation is too low. Thresholds and confidence must be versioned, integer-only, and applied consistently to first and appeal rounds.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Read thresholds from the round's frozen configuration.
- Calculate confidence as winningWeight × 10,000 ÷ totalWeight for conclusive candidates.
- Return Inconclusive when count, total weight, confidence, tie, or zero-participation conditions fail.
- Expose reason codes for projection and user explanation.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- Validate basis-point bounds and multiplication order.
- Apply deterministic rounding with documented direction.
- Prevent current governance values from changing an open round.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Boundary tests immediately below, at, and above each threshold.
- Fuzz tests for confidence arithmetic and rounding.
- First-round versus appeal-round multiplier tests.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.
