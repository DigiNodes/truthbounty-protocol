# V2-SC-011 — Implement Verification Round Manager and Frozen Participation Snapshot

## Overview

Implement reusable round creation, closure, parameter snapshots, participant indexing, and round-state queries.

## Problem Context

First and appeal rounds must share deterministic timing and participation semantics. Reading mutable configuration after a round opens would make identical votes settle differently.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Create first and appeal rounds with frozen start, deadline, stake bounds, weight cap, thresholds, and parameter version.
- Close rounds permissionlessly after the deadline and reject further submissions.
- Expose bounded participant access and aggregate-ready frozen records.
- Emit round-opened and round-closed events with all projection identifiers.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- A round snapshot must be immutable after opening.
- Prevent overlapping active rounds of the same type for one claim.
- Avoid unbounded state-changing loops when closing or querying.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- First-round and appeal-round creation tests.
- Exact deadline, duplicate round, overlap, and pause tests.
- Regression test proving later config updates do not affect an open round.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.

## Acceptance Criteria

- [ ] Every verification belongs to one immutable round snapshot.
- [ ] Closed rounds reject votes.
- [ ] Round data is sufficient for deterministic aggregation.
- [ ] Participant access is gas-bounded.
- [ ] All new and existing relevant tests pass on the final commit.
