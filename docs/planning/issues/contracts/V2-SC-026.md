# V2-SC-026 — Implement Production Role Topology and Timelock Ownership

## Overview

Implement and test the canonical role graph centered on TimelockController and a pause-only 3-of-5 guardian multisig address.

## Problem Context

Production administration must not remain with an EOA or a broadly privileged default admin. Roles need explicit administrators, delays, and separation of powers.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Define proposer, executor, canceller, parameter, upgrader, treasury, root publisher, and guardian roles with explicit administrators.
- Transfer module administration to the timelock and renounce deployer privileges during finalization.
- Enforce minimum 48-hour economic-parameter and 7-day upgrade delays.
- Export role topology for deployment manifests.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- No EOA default admin after deployment finalization.
- Guardian cannot unpause, upgrade, transfer treasury funds, or change parameters.
- Role grants and revocations must be timelocked and emitted.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Role matrix positive and negative tests.
- Deployment finalization test proving deployer has no residual authority.
- Delay-boundary and unauthorized administration tests.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.

## Acceptance Criteria

- [ ] Every privileged function maps to one least-privilege role.
- [ ] Role administrators are documented and machine-exportable.
- [ ] Required delays cannot be shortened below specification minimums.
- [ ] No orphaned or circular admin relationship exists.
- [ ] All new and existing relevant tests pass on the final commit.
