# V2-SC-030 — Implement Governed Parameter Change and Version Activation Flow

## Overview

Implement proposal-to-timelock activation of new configuration versions and consumer notifications.

## Problem Context

Parameter versions exist, but the governance execution path must validate delays, bounds, activation time, and non-retroactivity as one atomic process.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Encode parameter updates as creation and activation of a complete validated version.
- Require at least the economic-parameter timelock and prevent shortening below the minimum.
- Emit proposed, queued, activated, and superseded version events.
- Ensure open claims and rounds continue using their frozen version.
- Expose current and scheduled versions for deployment and indexer consumers.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- Reject partial version mutation, invalid bounds, and retroactive effective times.
- Guardian cannot activate or edit parameter versions.
- Failed activation leaves the current version unchanged.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Valid governance lifecycle and scheduled activation tests.
- Early, invalid, partial, guardian, and open-claim non-retroactivity tests.
- Event and registry reconciliation test.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.
