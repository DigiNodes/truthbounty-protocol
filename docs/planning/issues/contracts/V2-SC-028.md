# V2-SC-028 — Implement Operation-Scoped Emergency Pause Controller

## Overview

Implement operation-scoped pause escalation, audit history, and governance-controlled recovery.

## Problem Context

Security incidents require rapid containment without granting the guardian broad financial or outcome authority. A single global pause or reversible guardian switch is insufficiently constrained.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Define pause keys for claim creation, evidence, verification, challenges, withdrawals, treasury execution, and upgrades.
- Allow the guardian multisig to escalate approved pauses but not unpause.
- Require governance/timelock recovery with reason and validation reference.
- Provide fail-closed modifiers or hooks and emit complete pause history.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- Pausing must not rewrite claim states or accounting.
- Guardian cannot transfer funds, upgrade, change parameters, or settle claims.
- Unknown operation keys and lower-level escalation attempts must revert.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Per-operation pause and unaffected-read tests.
- Guardian escalation, forbidden unpause, governed recovery, and audit-history tests.
- Dependency-call failure test proving fail-closed behavior.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.

## Acceptance Criteria

- [ ] Each critical operation can be independently blocked.
- [ ] Reads and event history remain available.
- [ ] Only governance recovery can lift pauses.
- [ ] Pause behavior is included in deployment verification.
- [ ] All new and existing relevant tests pass on the final commit.
- [ ] Static analysis and formatting introduce no new unresolved finding.
- [ ] Documentation and generated artifacts affected by the change are current.
- [ ] The pull request maps evidence to every acceptance criterion.

## Deliverables

- Evidence of commands run and their results.
