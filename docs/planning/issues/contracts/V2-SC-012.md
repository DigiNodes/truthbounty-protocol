# V2-SC-012 — Implement Stake Unlock, Refund, and Settlement Hooks

## Overview

Implement idempotent module hooks that convert frozen locks into refundable principal, claimable rewards, slash allocations, or continued dispute locks.

## Problem Context

StakeVault requires narrowly scoped hooks for later settlement modules. Broad transfer authority would recreate the treasury and rescue risks identified in the audit.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Define typed hook methods for round rollover, conclusive settlement, inconclusive refund, appeal carry-forward, and final unlock.
- Authorize each hook to the minimum registered module and validate claim, round, asset, and amount.
- Make repeated or conflicting settlement instructions revert without partial accounting.
- Emit granular lock-transition events.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- No hook may transfer funds directly to arbitrary recipients.
- Prevent double unlock, double slash, and cross-round consumption.
- Preserve aggregate custody invariants on every state change.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Authorized and unauthorized hook tests.
- Duplicate, partial, over-allocation, wrong-asset, and wrong-round tests.
- Invariant test across randomized lock-transition sequences.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.
