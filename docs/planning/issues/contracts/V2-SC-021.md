# V2-SC-021 — Implement Timelocked Treasury Vault

## Overview

Implement a treasury vault for only emitted treasury allocations and timelocked, purpose-recorded transfers.

## Problem Context

Treasury funds need explicit ownership and delayed governance control without gaining access to user principal or settlement authority.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Accept allocations only from registered settlement/slashing modules.
- Track treasury balances separately by asset and source claim.
- Require timelock execution with recipient, asset, amount, and purpose digest.
- Emit allocation and transfer events and expose reconciliation views.
- Reject transfers that touch user claimable obligations.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- No EOA or guardian transfer authority.
- No claim settlement, winner selection, or weight mutation capability.
- Reentrancy protection, zero-address checks, and safe transfers.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Authorized allocation and timelocked transfer tests.
- EOA, guardian, early execution, overdraw, wrong asset, and reentrancy tests.
- Invariant proving treasury transfers cannot reduce user obligations.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.

## Acceptance Criteria

- [ ] Treasury custody equals allocations minus governed transfers.
- [ ] Every transfer is timelocked and emitted.
- [ ] User funds are unreachable.
- [ ] No unrestricted rescue of protocol assets exists.
- [ ] All new and existing relevant tests pass on the final commit.
- [ ] Static analysis and formatting introduce no new unresolved finding.
- [ ] Documentation and generated artifacts affected by the change are current.
- [ ] The pull request maps evidence to every acceptance criterion.
