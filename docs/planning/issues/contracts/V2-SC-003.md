# V2-SC-003 — Define Versioned Canonical Event Schema

## Overview

Define and test the event families required to reconstruct every lifecycle, accounting, governance, pause, and upgrade transition.

## Problem Context

The V2 indexer must rebuild authoritative state from events, but current contracts do not provide one complete, versioned projection contract. Missing identifiers or allocation fields would make replay nondeterministic.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Specify event signatures and indexed fields for claims, evidence, stake, verification, rounds, outcomes, disputes, rewards, slashing, withdrawals, treasury, parameters, reputation roots, roles, pauses, and upgrades.
- Include claim or allocation identifiers, round, actors, asset, amount, parameter version, and resulting state where required.
- Create a machine-readable event-schema export format and human-readable event catalogue.
- Document breaking-change and versioning rules.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- Avoid emitting evidence content, signatures, secrets, or unnecessary personal data.
- Ensure indexed fields support filtering without duplicating authority.
- Guarantee financial events reconcile with storage entitlements.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Event emission tests for each authoritative transition.
- Schema-to-ABI consistency tests.
- Projection fixture that reconstructs a representative claim lifecycle from logs only.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.

## Acceptance Criteria

- [ ] Every required event family in specification §20 is represented.
- [ ] A consumer can identify release and parameter version.
- [ ] Financial event totals match stored accounting.
- [ ] Schema generation is deterministic and CI-ready.
- [ ] All new and existing relevant tests pass on the final commit.
- [ ] Static analysis and formatting introduce no new unresolved finding.
- [ ] Documentation and generated artifacts affected by the change are current.
- [ ] The pull request maps evidence to every acceptance criterion.
