# V2-SC-040 — Audit Legacy Exclusion and Canonical Release Readiness

## Overview

Create an automated and human-reviewable release-readiness audit for the canonical contract suite.

## Problem Context

V2 is not ready merely because modules exist. The final epic gate must prove that legacy authority is unreachable, artifacts are consistent, tests cover invariants, and deployment outputs are safe for API/frontend consumption.

This issue belongs to **V2-EPIC-SC-001 — Canonical Contract Topology and Deployment**. Existing repository issues are historical only; their titles, labels, closure state, or partial implementations do not satisfy this issue.

## Technical Scope

- Inventory all deployable contracts and classify canonical, reference, transitional, deprecated, or removed.
- Assert TruthBountyClaims is absent and TruthBountyWeighted is not a canonical consumer target.
- Run compilation, unit, integration, invariant, fuzz, static analysis, gas, storage, deployment, artifact, role, and accounting checks.
- Verify manifest/ABI/event/address consistency and produce a signed readiness report template.
- List residual risks and block release on critical or high findings.

The contributor must begin by auditing current files that overlap this scope. Reusable logic may be retained only when it conforms to the governing V2 interfaces, events, authority boundaries, and tests. The pull request must identify reused, replaced, and deprecated paths.

## Security and Integrity Requirements

- No checklist item may be satisfied by legacy issue closure alone.
- Do not expose security-sensitive exploit detail in public output before coordinated review.
- No warning-only bypass for canonical blockers.
- Preserve blockchain authority and every applicable protocol invariant.
- Do not add secrets, production credentials, dummy production addresses, backend settlement authority, or Stellar/Freighter runtime dependencies.

## Required Tests

- Automated legacy-address and deprecated-selector scans.
- Full local release pipeline test.
- Deliberate blocker fixtures proving readiness fails.
- Report schema and checksum tests.
- Run the repository’s complete required Hardhat and Foundry suites and report unrelated pre-existing failures separately.
- Add regression coverage for every defect or unsafe legacy behavior removed by this work.

## Acceptance Criteria

- [ ] The report maps every V2-SC issue and protocol invariant to evidence.
- [ ] No legacy authority path appears in deployment or artifacts.
- [ ] All required checks pass on the same commit.
- [ ] API/frontend receive one approved release package.
- [ ] All new and existing relevant tests pass on the final commit.
- [ ] Static analysis and formatting introduce no new unresolved finding.
- [ ] Documentation and generated artifacts affected by the change are current.
- [ ] The pull request maps evidence to every acceptance criterion.

## Deliverables

- Production-quality Solidity, interfaces, libraries, deployment code, or test code required by the scope.
- Unit and higher-level tests described above.
- NatSpec and contract-specific technical documentation.
- A pull-request summary covering architecture, security analysis, gas or storage impact, migration implications, and residual risks.
- Evidence of commands run and their results.
